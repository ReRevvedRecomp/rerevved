# Automated and AI-assisted contributions

If automated or AI assistance is used, the work follows the same contribution
and evidence contract as any other work. The contributor owns every submitted
claim and must be able to explain its source, scope, and supporting evidence.

Automated output is not guest code or runtime evidence. A durable claim starts from
the generated code, a guest code locator, a reproducible tool result, or a
captured runtime observation. Read
[evidence-and-claims.md](evidence-and-claims.md) before promoting an
observation into documentation, configuration, or source.

Commit subjects follow the typed format in
[`CONTRIBUTING.md`](../../CONTRIBUTING.md#commit-subjects).

## Public contract

Tracked documentation describes current behavior and its supporting method or
evidence. Keep branch state, work queues, session narration, machine paths, and
private title material out of the public tier.

Put each settled fact in one canonical guide and link to it elsewhere. Preserve
addresses, offsets, hashes, tool names, uncertainty, and provenance citations
when they carry the claim.

The public boundary applies to all tracked Markdown and structured data. Do not
include prompts, assignments, handoffs, work-session plans, self-review metadata,
private paths, or internal milestone identifiers. Structured records retain
evidence and current conclusions. Tests assert semantic contracts.
